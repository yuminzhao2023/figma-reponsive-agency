# Figma 响应式页面还原练习

基于 [Figma 设计文件](https://www.figma.com/design/r6ykWotH1e5RyXBu7UMNnF/) 的前端还原练习。设计稿由原设计作者创作；本仓库仅记录本轮 React 前端实现，不代表真实客户项目。

三端完整 UI 参考图已保存至 [`design/`](design/README.md)：[桌面](design/desktop.png)、[平板](design/tablet.png)、[手机](design/mobile.png)，均为 Figma 原尺寸导出。

## 技术与运行

React、TypeScript、Vite、普通 CSS，使用 npm 管理依赖。

```bash
npm ci
npm run dev
```

在终端输出的本地地址打开页面。检查命令：`npm run typecheck`、`npm run lint`、`npm run build`。

## 已实现范围

已实现整页的导航、首屏、品牌介绍、服务卡片、客户评价轮播、联系表单、博客和页脚，对照 Desktop `1:998`、Tablet `2:451`、Mobile `2:243`。

- 桌面显示 8 张服务卡片、3 张博客卡片，评价图文横排，联系信息与表单分列。
- 平板和手机默认显示 4 张服务卡片、2 张博客卡片；评价图文竖排，表单位于联系信息下方。
- 页脚在桌面为四列，平板为两行，手机按品牌、订阅、联系、探索链接排序。

## 素材与交互

- 图片、Logo、菜单和图标来自上述 Figma 文件，已下载至 `public/assets/`，页面不依赖临时 Figma 链接。新增素材对应：评价图片、形状与控制图标 `1:1568`；博客图片 `1:1469`、`1:1422`、`1:1375`；联系图标 `1:1041`；页脚 Logo `1:1072`；社交、页脚联系图标来自 `2:451`；标题装饰来自 `1:1014`—`1:1016` 及三端对应图层。
- `View more` 的目标行为在设计中未定义；这里暂定为展开其余 4 张卡片，再次点击可收起。
- `Let’s talk`、各报价链接和菜单中的 Contact 现在滚动到联系区。菜单支持键盘打开、Escape 关闭和焦点返回；点击页面外部、再次点击按钮、选择链接或 Tab 移出菜单也会关闭。
- 导航弹层以右上角为原点，180 ms 淡入并轻微下移、缩放，120 ms 收起。关闭时不接受点击和键盘焦点；尊重 `prefers-reduced-motion`，减少动态效果模式直接开关。
- 评价支持前后切换及圆点选择；手机稿未展示方向按钮，因此手机仅展示可点击、可用键盘操作的圆点。不自动播放。
- 评价切换采用先退出、后进入的 `out-in` 过渡，背景和容器高度固定，不叠加两段可见文案。图片约 140 ms 退出、300 ms 进入，入场位移 18 px；文字入场位移 12 px，较图片延后 40 ms。图片解码后再切换，连续点击在当前过渡完成后合并处理最新目标；开启 `prefers-reduced-motion` 时直接切换。
- 平板和手机稿的首条评价文案与桌面稿不同，分别按对应设计呈现；其余两条评价采用桌面稿内容适配窄屏。
- 窄屏博客 `View All` 暂定为展开第三张卡片，再次点击收起；桌面已展示全部三张，点击显示演示说明。
- 原设计没有提供完整文章正文、链接目标或条款内容，`Read more` 和条款按钮打开注明演示状态的对话框，不编造正文；对话框支持 Escape 关闭。
- 联系和订阅表单提供关联的 label、必填和邮箱格式校验。提交仅在本地显示演示反馈，不保存、发送输入内容或创建真实订阅。设计中的地址、邮箱和电话仅作为示例文案展示。
- 社交按钮、Our Team、Shop 和 Career 未提供目标地址，点击显示演示反馈。

## 已知限制

- 设计使用 Proxima Nova；本轮未取得可用于网页的字体文件，浏览器使用系统备用字体。文字宽度、换行和字形会与设计略有差异。
- 品牌介绍图片用设计原图及形状素材裁切，浏览器对 SVG mask 的边缘渲染可能与 Figma 略有不同。
- 窄屏评价按同宽度下最长文案预留高度，切换不会推动下方内容；备用字体仍会影响预留高度与原稿的差异。新增表单的演示说明是为区分真实提交而添加的文字。
- 原始导出素材仍保留在 `public/assets/` 供追溯；页面使用 `public/assets/optimized/` 中的 WebP 派生文件。照片经过有损压缩，细微纹理可能有差异；Logo 使用无损编码。

## 图片与滚动性能

原始位图合计约 55.60 MiB，多张照片宽达 4096 px。页面现在通过 `srcSet`、`sizes` 按显示尺寸和设备像素比选图，保留原宽高比及现有 CSS 裁切；选图时考虑 `object-fit: cover` 的实际像素需求。

- 首屏照片保持立即加载，并设置高优先级；其余大图使用浏览器原生懒加载。
- 位图设置异步解码和固有宽高，减少图片处理对页面呈现的影响。
- 窄屏隐藏的服务和博客图片在展开前不会下载；评价仅请求当前条目的照片。
- 新增开发依赖 `sharp`，仅用于生成图片，不进入浏览器运行代码。重新生成命令：

```bash
npm run images:optimize
```

脚本保留原图，生成 WebP 文件及 `src/image-manifest.json`。更换原始素材后需重新执行命令；生成结果应一同纳入版本管理。普通开发与构建不重复转码。

## 实现与验证

`src/App.tsx` 保留原有首轮区块，`src/PageSections.tsx` 负责后半页与演示交互，`src/lower-page.css` 定义后半页布局及响应式样式；`src/images.ts` 管理图片加载属性，`scripts/optimize-images.mjs` 负责生成网页图片。

2026-11-09 已使用独立无头 Chrome 在 1440、1024、768、390、375 px 截图检查，并实际操作菜单、轮播、展开按钮、对话框及表单。具体执行记录和剩余差异见 `STATUS.md`。
